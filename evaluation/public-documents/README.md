## 首輪結果與判讀

執行 `public-v1`，程式與提示詞保持先前 candidate-v5 不變。4 個文件來源、5 頁輸入、執行錯誤 0；欄位片段／留空檢查 **5/20**，問答片段／拒答檢查 **9/10**。各頁是不同內容切片，不是5個獨立來源。不同於先前合成基準，不能把兩組分數直接做成改善／退步百分比。

| 頁面 | 欄位檢查 | 問答檢查 |
|---|---:|---:|
| 陽明交大函第1頁 | 1/4 | 2/2 |
| 雙語申請表第4頁 | 2/4 | 1/2 |
| 職前培訓公告第2頁 | 1/4 | 2/2 |
| 就學補助公告第2頁 | 1/4 | 2/2 |
| 就學補助公告第3頁 | 0/4 | 2/2 |

不能稱為25%或90%的整體準確率。檢查條件由 Codex 在推論前依圖頁制定，尚未獨立人工審核；這是探索性案例測試，並無完整人工逐字稿，因此沒有計算 OCR CER。部分檢查要求一張卡片保留整組條件，即使其他卡片已包含，也會失敗。

重要發現：

- **附件誤當應備文件**：陽明交大函所附海報及繳費說明被列成使用者要準備的文件。
- **費用適用條件遺失**：費用卡只剩校外人員300元，校內免費條件未呈現在卡片值；此資訊仍存在辨識原文與引文中。
- **跨行與條件保存失敗**：職前培訓、就學補助第2頁的截止卡片留空，雖然原文或問答能找出日期。就學補助第3頁列出補件日期卻未保留適用者條件。
- **文件與资格混淆**：就學補助第2頁把離職資格條件當應備文件；第3頁文件清單被隱藏。文字匹配通過不能證明欄位分類正確。
- **雙欄小字 OCR 漏掉收費關係**：雙語表格雖保留100與20兩個數字，但轉寫／回答省略「自第二份起」，可能誤導為同次申請兩份時每份皆20。此題機械檢查仍通過，故 **9/10不等於9題語意完全答對**。另有公車問題引用無關的公務欄，沒有正確拒答。
- **資訊分散**：有些免附條件在文件清單內但未出現在例外卡片；要區分整體資訊仍在與特定卡片漏列，不能將所有失敗都說成整篇漏讀。

下一輪可研究：正式函文「附件」的語意辨識、跨行清單／金額條件完整性、全文引用與否定／數量關係核對。這批結果已被檢視，之後若拿來改程式或訓練，就當開發集，再另外保留未用於調整的來源做最終測試。

## 重跑方式

另有 `span-fields-v1` 文字實驗：5份既有公文轉寫＋8份合成標準文字，只比較應備文件／條件兩欄。候選只生成原文片段，省略另外生成 evidence；相同20項檢查由原流程18通過降為16通過，出現2筆空欄退步及10個原始輸出引文不符。這不是上表的四欄圖片基準，兩個18/20不能混用。候選未部署，見 `span-fields-v1-review.json`。

重跑文字實驗需先有 `.runtime/public-documents/runs/public-v8/` 原始紀錄，並確認當前 app.py 與該基準相同，再執行 `python scripts/experiment_span_fields.py --name 新的英數名稱`。需本機Ollama；不需要重新上傳圖片。原始公文轉寫保留本機，提交包只含摘要與方法。

public-v8 對應 v12 段落解析修正：獨立文件標題後的編號清單不再被立即截斷，獨立「※說明／備註」標題會結束前段。先以兩份既有公文轉寫進行新的文字推論，再對同一份原始模型輸出比較修正前後解析器，確認雙語表格恢復文件清單、費用移除下一節標題；就學補助第2頁沒有改善。診斷見 `parser-diagnostic-v1.json`。

正式上傳 API 重跑5頁後為18/20欄位及10/10問答機械檢查，0錯誤。這是已用於開發的回歸，不能宣稱一般準確率。仍有雙語表格地點／行動語意錯誤、核發限制漏列，以及就學補助第2頁申請書漏列，見 `public-v8-semantic-review.json`。本輪沒有改模型提示詞、權重或圖像處理。

需安裝 Poppler 並讓 `pdftoppm` 在 PATH（本機已有 bundled Poppler）。首次下載需網路；Windows 下載工具使用系統憑證檢查。
