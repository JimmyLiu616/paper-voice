# 客語公文重點解說 v2

日期：2026-10-02。已接入統一語言選單的客語路徑，推論全本機，使用時無人工確認勾選。**這是有支援範圍的公文重點解說，不是任意中文的通用客語翻譯。句型與語音尚未經母語者驗證。**

## 改變了什麼

原先客語只做固定整句轉換。新版將完整來源拆成有證據的語意框架：日期時間、截止方向、行動、文件的且／或、年齡比較、其他人的費用、已完成事項、委託文件、紙本限制、假日順延及不退費。

Gemma 3 4B 提出結構化欄位，程式依有限範圍的原文語法獨立核對。只有全部欄位、順序、段落數與來源規則一致才接受模型提案。模型提案不符、逾時或忙碌時，僅在原文已完整通過規則的情況使用來源規則結果，回傳 `extraction_status=source_rules`；不會冒稱 AI 抽取成功。任一原文段落不支援就不呼叫 TTS，也不播放局部成功內容。

文字由固定客語草稿句型組合，日期及數字直接填入，再做數字順序檢查與讀音轉換。原有 TTS 四縣／海陸可切換，兩腔共用文字稿，未宣稱各腔自然口語翻譯。舊 `/api/hakka-translation` 保留相容；主畫面使用新版 `/api/narrate`，另有 `/api/hakka-notice-plan` 可查看同一份結構化結果。

## 問答引文的修復

實際網頁測試發現，Gemma 問答可能僅回答與引用「其他人須繳500元」，漏掉同句前半的「只有65歲以上才免費」。新版 `/api/ask` 在原本回答及引文之外提供 `narration_evidence`：回到文件取唯一對應的完整段落，並保留相鄰、以「但／惟／若／如」等明確連接的條件段落。客語用這份較完整來源解說，畫面明示「依據原文解說」，其他語言仍朗讀原回答。

重複且不唯一的來源不任選其中一段。相鄰「本活動免費。惟材料費另收。」不會只唸免費。這是保守的段落恢復規則，不能保證找出文件其他位置的所有相關例外；無法處理的整段保留中文。範圍外的詞句、未知附帶條件、混合文件且／或與複雜跨段關係仍可能拒絕解說。

## 實測證據

- `local-probe.json`：本機 Gemma 實際執行的 11 個自製案例。8 個支援案例完成組句，3 個範圍外／附帶未知條件案例整體拒絕。8 個成功案例中只有 2 個模型提案完全通過欄位比對；另外 6 個使用已驗證的原文規則退回路徑。這不是 8/8 自由翻譯準確率。
- `phonemes.json`：8 個成功案例 × 四縣／海陸，共 16 份發音字典／音標檢查，未見未知字詞或音標。
- `live-audio.json`：實際新版 `/api/narrate` 合成「期限＋年齡費用」兩段完整內容，四縣 11.611 秒、海陸 12.017 秒音檔，均為 22,050 Hz、無 `speech_error`。總處理時間約 48.76 與 41.12 秒；兩次均有明示使用原文規則退回路徑。
- 自動化回歸涵蓋年齡門檻反轉、日期時間刪除、金額改寫、漏段／重排、未知例外、整份檢查後才啟動 TTS，以及問答短引文恢復。最終完整回歸：333 項 Python、48 項 JavaScript 測試通過。

網頁端最終實測見 `browser-check.json` 與 `browser-demo.jpg`：短引文成功恢復年齡／費用與相鄰例外，四縣語音自動播放完成（14.745 秒），未見前端錯誤。

權重、測試音檔與私人執行環境不放進 GitHub；語音證據的 SHA-256 與時長留在報告。`qavit/mt5-small-hak` 沒有接入正式流程，對照測試見相鄰 `hakka-mt5-v1`。

## 操作

1. 在首頁選「貼上文字」，貼入 `samples/hakka-notice.txt`，按「幫我讀懂」。
2. 在「提問與朗讀」選客語，再選四縣或海陸。
3. 問「需要繳費嗎？」或「最晚什麼時候要完成？」。
4. 客語解說自動合成播放，可展開「查看本次解說依據」核對。切換腔調後按「用此語言重讀」。

關鍵程式：`scripts/hakka_notice.py`、`app.py`、`static/narrator.js`。新的 `/api/hakka-notice-plan` 與其他寫入型 API 一樣要求本機 UI 標頭。
