# 未採用候選：同時拒絕三類已觀察到的非答案

2026-10-02。Ministral／Gemma 配對試驗暴露出：來源中確實存在的字串，也可能不適合作為欄位答案。這次保留正式 Gemma 模型、提示詞與權重，僅增加有限格式檢查。

- 公報中的獨立篇名（實例「內政篇」）不能充當地點，標為待核對。沒有以所有「篇」字結尾內容作全面判定。
- 電話標籤加空白底線不能充當聯絡方式，標為待核對；保留有實際號碼或電子信箱的內容。
- 空白答案或只有 `found=true` 等結構旗標的答案回傳 HTTP 502「這次回答格式異常，請重新提問。」這不表示文件沒有資訊，也不會自動生成替代答案。

`report.json` 是從 `ministral-core-v1` 保存的三筆實際輸出重播，沒有重新抽樣生成；三筆都成功攔截。重播程式 `scripts/replay_output_formats.py` 需要本機保存的原始實驗 JSONL。原始逐字稿未納入公開包，報告記錄其 SHA256；公開單元測試另包含可重跑的最小案例與相近合法輸入。

當時14項新增回歸加上既有測試，共111項Python測試通過（1項既有棄用警告），但圖片流程暴露退步：`public-v9`欄位仍18/20、問答由10/10降到9/10。移除錯誤地點也改變問答提示中的source_fields，公車問題錯誤地引用了證件段落。這說明單元測試通過不足以決定部署。

因此撤回篇名地點檢查，正式版僅保留另外兩項格式檢查，見 `../output-format-v2/`。本目錄的程式／測試是歷史快照，不是目前入口。`report.json`只證明當時三筆重播通過，不能引用為目前三項皆已修好。

另試過問答只提供原文、不再附source_fields：首3題通過，第四題公車問題HTTP422後停止，沒有完整10題分數。再單獨重現該題，同樣因模型生成達長度上限而拒絕；見 `raw-only-failure.json`。`raw-only-runner.py`保存未完成實驗程式；前三題答案因程式在迴圈結束才保存而沒有留下，只保留終端通過紀錄，不能宣稱完整可重建結果。未採用此提示變更。
