# 結果回傳等待時間

前端每次狀態查詢後的間隔由 1.3 秒縮短為 0.4 秒。只改本機狀態查詢，不改模型提示、辨識、欄位整理與語音。切換文件時仍以原有 run 檢查丟棄舊結果。

同一份真實工作由兩個客戶端以原／新間隔查詢，共 6 次圖片辨識（兩張原創素材各三次）。模型完成至客戶端收到結果的中位數：0.7677 → 0.1475 秒；每一對節省時間的中位數 0.5774 秒。兩者是不同統計量。每對收到的是同一份結果，模型沒有重算。

限制：這是 TestClient 下的 API 回傳延遲量測，不是瀏覽器繪製效能。每次結果剛好落在哪個查詢間隔會影響時間，不能保證每張圖都快。查詢次數從每份 6–8 次增加至 16–22 次，僅在正在處理文件時執行。完整資料及重測腳本見 `plan.json`、`rows.json`、`summary.json` 及 `scripts/benchmark_result_delivery.py`。

真實瀏覽器另確認新版本仍能完成社區活動辨識（畫面顯示 6.7 秒）；這只是一次操作，不作為一般速度保證。畫面中「智型手機」等字詞仍可能辨識不完整，必須核對原圖。30 項 JavaScript 測試與語法檢查通過；後端正式程式未修改，沿用前輪 231 項通過紀錄。
