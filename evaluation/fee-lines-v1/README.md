# 逐行對應的費用清單修正

2026-10-02。public-v8與public-v10最後一頁的Windows OCR參考完全相同，Gemma逐字稿只在居留證句子多出一個句號。這個差異發生在文件清單，不是期限或金額；不能直接認定兩项欄位退步都是OCR讀錯數字造成。

後續保存的一次真實欄位生成，費用value省略了兩項編號、保留換行；兩行內容各自在來源中，但拼在一起不再是連續字串。舊規則因此拒絕整段。這是格式與來源對應問題，優先嘗試程式修正，沒有更新模型權重。

新規則只處理唯一明確費用標題：多行value必須每行逐字出現在來源段落、順序一致且不得重複利用同一位置，純數字邊界也不能只匹配另一金額的尾部；全部成立才取回完整原文段落，連同編號、身分及金額上限。任一行的數字／對象改動仍拒絕。不依字串相似度改寫數字，也不把不相連片段作為引文輸出。

固定輸出對照 `replay.json`：舊版費用待核對，新版保留兩個費率、對象及上限；其餘六欄完全相同。來源是先前保存的模型輸出，沒有重抽樣挑選結果。9項新增測試包含數字／對象錯誤、順序顛倒、重複片段及部分數字；完整Python測試117項通過（1項既有棄用警告）。這些不是模型準確率，也不是fine-tuning成效。

重播指令：`python scripts/replay_fee_list.py`，需要本機保存的 `.runtime/format-control-v1/result.json` 與public-v10程式快照；不覆寫既有報告。公开最小回歸可用 `python -m pytest tests/test_fee_source_lines.py`。

圖片流程以 `python scripts/evaluate_public_documents.py --name public-v11 --isolated` 執行同一API、圖片處理、Windows OCR及真實Ollama；隔離程序不更換正式服務。各階段實際模型輸出留在本機 `generations.jsonl`，不放入公開包。這是評測工具新增的診斷紀錄，正式使用者上傳流程未開啟逐字輸出記錄。

完成結果：5頁、欄位18/20、問答10/10、0執行錯誤，保存20次模型生成。將這輪5份真實擷取輸出分別送入新舊驗證器，35欄結果全部相同；所以16/20回到18/20不是新規則在這輪改善2題的證據。修正效果僅由先前保存的特定失敗輸出證明。public-v10較低結果仍保留，公報地點、行動、核發限制及補助申請書漏列仍未解決。詳見 `../public-documents/public-v11-review.json`。

隔離回歸結束後才重啟正式服務；`/api/health`的app SHA256與本次受測版本一致。沒有微調、換模型或改提示詞。
